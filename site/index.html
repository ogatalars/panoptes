Why is the SLO stricter than the SLA? The SLA is the promise made to users; the SLO is the internal alarm set tighter, so the team notices and reacts while there is still room before the public promise is broken. An SLI here is the share of probes that answered 2xx within the latency threshold over the last 30 days.

Measurement honesty

Probes run on GitHub Actions cron, which is best-effort: runs are often delayed and sometimes skipped. The SLI is computed over the probes that actually ran, so a skipped probe is a blind spot, not a success. The table shows how many probes arrived versus how many the schedule promised.

Incidents

When a target goes down or a fast burn-rate alert fires, Panoptes opens (or updates) one GitHub issue per target with the facts, the probe timeline and, when a model is configured, an AI-drafted postmortem. The AI only writes text; it never changes code or config. See incident issues.
